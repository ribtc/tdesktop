# 无数量上限的多账号管理与独立代理

状态：规格已进入实施拆分。本文不代表实现或测试已完成。

## 问题

客户端限制可登录账号数量，多账号操作缺少适合大量账号的快速切换和管理界面。代理配置由所有账号共享，无法为账号固定网络出口，也无法保证代理失效后账号停止联网。

## 方案

取消人为账号数量上限，按指定设计提供头像快速切换、账号管理和代理管理。每个账号绑定自己的代理配置，从登录前到后台运行始终使用该绑定。首版支持 SOCKS5 和 MTProto。

未绑定、代理检测未通过、代理失效或所用功能无法满足隔离要求时停止对应联网活动，并显示原因。不得自动直连、读取系统代理作为替代，或借用未绑定的代理。

用户可明确把同一代理绑定给多个账号。各账号连接、状态及操作目标保持独立，但界面提示它们可能共用公网出口 IP。代理隔离不保证不同代理服务提供不同出口 IP。

## 用户故事

1. 作为多账号用户，我希望添加超过原有数量限制的账号，以便集中管理自己的账号。
2. 作为多账号用户，我希望重启后所有账号都能恢复，以免新增账号丢失或覆盖旧账号。
3. 作为用户，我希望在登录前绑定并检测代理，以免验证码和认证请求使用错误出口。
4. 作为用户，我希望点击头像切换当前账号，以便快速处理不同账号的会话。
5. 作为用户，我希望切换时其他账号继续使用原代理联网，以免窗口操作改变后台出口。
6. 作为用户，我希望头像显示未读计数和当前账号，以免把操作发给错误账号。
7. 作为用户，我希望通过全部账号入口搜索名称、手机号和标签，以便找到头像列外的账号。
8. 作为用户，我希望按分组和连接状态筛选、分页查看账号，以便管理数百个账号。
9. 作为用户，我希望批量移动分组和绑定代理，以便减少重复操作。
10. 作为用户，我希望批量操作明确显示作用范围，以免把当前页操作应用到全部账号。
11. 作为用户，我希望新增和编辑 SOCKS5 代理及认证信息，以便为账号选择出口。
12. 作为用户，我希望新增和编辑 MTProto 代理及密钥，以便通过该协议访问 Telegram。
13. 作为用户，我希望从文本文件和剪贴板导入代理并先预览，以便修正格式错误后再保存。
14. 作为用户，我希望看到代理可用性和实测延迟，以便选择可连接的代理。
15. 作为用户，我希望设置代理连接的目标地址族偏好，以便适配 IPv4 或 IPv6 网络。
16. 作为用户，我希望明确知道多个账号正在共享代理，以便自行决定是否接受共用出口 IP。
17. 作为用户，我希望代理失效时账号立即进入阻断状态，以免静默暴露其他出口。
18. 作为用户，我希望编辑、替换或删除绑定代理时先停用旧连接，以免请求在两个出口间混用。
19. 作为用户，我希望看到当前代理无法支持的功能及原因，以免把隔离限制误认为软件卡死。
20. 作为升级用户，我希望保留登录态、账号数据和旧代理，并在完成绑定后恢复联网，以免升级造成数据损失或自动共享出口。
21. 作为管理大量账号的用户，我希望 500 个账号能持续联网并保持界面可操作，以便处理后台到达的消息。

## 已确认的产品决定

- 首轮容量目标为 500 个已登录账号同时联网；不以后台休眠替代此目标。
- 隔离范围包括账号认证、消息、上传下载、相关 DNS、通话与内置网页。不能经指定代理安全执行的功能可以暂时禁用，必须给出提示。
- 旧账号保留登录态和全部本地数据。旧代理进入代理库，但不自动为账号绑定；迁移后的账号在用户完成绑定前阻断。
- 首版协议为 SOCKS5 和 MTProto。两种协议都必须支持独立账号绑定、共享提示、保存恢复及失效阻断。
- 账号凭据批量导入和批量修改个人资料另行定义。

## 实现默认值

以下默认值用于实施和验收，不增加已确认的产品范围。

### 账号与代理生命周期

- 代理库保存可复用配置，账号保存稳定绑定关系。绑定不依赖列表位置或当前窗口的账号。
- 每个账号独立持有有效配置、连接状态及请求生命周期。切换当前账号不修改代理。
- 未绑定和检测中不发送账号业务流量。检测只允许访问待验证代理及经该代理访问必要目标。
- 新绑定通过检测后才可开始业务连接。失败后只重试该绑定，不从全局代理池自动轮换。
- 编辑共享代理的连接参数前关闭所有受影响账号的旧连接；不影响绑定其他代理的账号。旧检测结果及旧连接回调不能重新放行业务请求。
- 删除代理或清空代理库时，先展示受影响账号并确认；删除后这些账号保持登录态但进入未绑定阻断状态。
- 修改代理备注不重建业务连接。网络故障不删除账号认证数据。

### 代理输入与能力

- 首版代理入口使用 IPv4 或 IPv6 字面地址，避免为连接代理而先进行本机 DNS 查询。旧域名配置保留且显示不可用于当前隔离模式，不能静默解析或删除。
- SOCKS5 支持无认证和用户名/密码认证。目标域名需经代理解析；不使用本地 DNS 作为失败回退。
- MTProto 使用客户端已有密钥校验能力。TLS 仿真密钥中包含的域名用于握手，不等同于需要本机解析的代理入口地址。
- MTProto 连接只访问所绑定代理。不能把其转换为普通 HTTP 组件的直连配置。
- 不按代理类型一律禁用网页或音视频。通过 MTProto 获取的网页文件、页面数据和直播媒体分片纳入正常支持，验证其经过绑定代理。
- 任意网页的 WebView 请求、普通 HTTP 请求、双向实时通话媒体及通话信令分别核对出口。能够满足隔离要求的路径保持可用；只有无法满足的具体路径才阻断并提示。信令成功不能替代媒体连接验证。
- 保留旧 HTTP、WEB 配置，但首版不将其作为账号联网候选，不自动转换成 SOCKS5 或 MTProto。
- 不为账号自动打开外部浏览器作为受限内置网页的替代路径。

### 管理界面

- 头像列复现选定设计的当前账号标记、未读徽标、全部账号和添加入口。大量账号通过滚动或全部账号管理页访问，不为所有账号常驻创建复杂页面。
- 账号搜索、分组、状态筛选及分页组合使用。跨页全选明确显示选中总数，操作前固定目标账号集合。
- 一个账号有一个管理分组，标签用于补充搜索。分组删除后账号回到未分组，不删除账号或代理绑定。
- 批量操作逐项反馈成功和失败，不将部分成功展示成全部成功。
- 代理表显示类型、地址、端口、备注、认证用户名、检测状态及绑定账号数。密码和 MTProto 密钥默认隐藏，不写入日志。
- 国家信息无法可靠获得时显示未知；不把示例国家或代理入口地址当作已检测的公网出口。
- 代理导入先解析和预览，确认后写入；错误项给出行号及原因。导入不自动绑定或检测所有账号。
- 无协议前缀的设计稿格式按 SOCKS5 解析。MTProto 使用带明确协议语义和密钥的链接，避免把密钥误当 SOCKS5 密码。
- 检测有并发上限和取消能力。以对应协议的实际握手和目标连接验证可用性，TCP 端口打开不等于代理可用。
- 地址族偏好应用到新导入配置，并供检测与业务连接共同使用。MTProto 由服务端选择的最终出口地址族无法由客户端保证，界面不能把它标成已验证的出口偏好。

### 数据与连接架构

- 同时去除创建、恢复、索引校验及切换入口的人为账号数量限制，保留输入长度、损坏数据和资源耗尽检查。
- 新设置使用可演进的持久化格式，不插入旧顺序二进制流的中间；迁移保留旧数据，重复启动不得重复导入或覆盖绑定。
- 登录前的账号对象即可拥有代理绑定；不能等到已认证会话建立后才应用隔离。
- 在账号级网络入口统一决定是否允许连接，并将配置传给 MTProto 和其他账号网络使用者。原生网页、通话、后台请求等无法复用该入口的路径必须单独适配或禁用。
- 枚举账号拥有的全部网络使用者，覆盖初始连接、重连、特殊配置、时间同步、文件重定向和辅助请求。不能只靠主请求路由证明隔离。
- 线程与网络池的共享不得共享账号认证、绑定或可变代理状态。容量优化以测量为依据，不为达到线程数目标削弱隔离。

## 验收方法

### 测试入口

尽量通过实际账号管理、绑定、登录和切换操作驱动行为，复用现有账号环境校验、窗口定位和界面输入工具。需要新增时，集中提供一套外部代理与目的端观察环境，记录连接去向及故障注入；不在产品代码中散布调试状态。

只观察用户行为和网络结果：保存恢复是否一致、操作影响了哪些账号、请求到达哪个代理、被阻断时是否仍有流量。设置字段或界面文案变化不能单独证明网络隔离。

### 双账号隔离

- 分别绑定 SOCKS5/SOCKS5、MTProto/MTProto 及 SOCKS5/MTProto，验证登录、后台收信、切换和常规文件传输。
- 用可区分的代理端日志与进程网络观测验证路由。监测本机 DNS、直接目的端连接和未绑定代理访问；仅验证正确代理收到流量不足以排除旁路。
- 覆盖未绑定、认证错误、连接中断、代理删除、共享代理编辑、绑定替换、检测取消和重启恢复。
- 故障时受影响账号停止业务流量，无关账号保持原连接。延迟回调、旧检测成功结果和重定向不能绕过阻断。
- 分别测试通过 MTProto 下载的网页文件、直播媒体分片、WebView 请求和双向通话媒体，验证可用性与出口。既要发现绕过代理的连接，也要防止把本可走 MTProto 的路径误禁用。
- 对禁用的通话、网页或下载路径验证明确提示和零启动流量。

### 界面、导入和恢复

- 验证至少 7 个账号的真实保存恢复路径，证明超过原有硬上限；另用 500 条记录覆盖虚拟化、分页和批量选择。
- 覆盖明文格式、协议链接、IPv6、空行、注释、非法端口、缺失密钥、重复项及部分无效输入。错误提示不回显认证秘密。
- 以指定设计节点为基准检查头像列和管理页面；覆盖窄窗口、缩放、长账号名及大未读数。
- 验证旧数据迁移不自动联网、不丢失登录态；重复迁移和损坏记录不能影响其他账号。

### 容量

建议基线为 500 个账号持续联网 30 分钟，期间抽样收发消息、传输文件、切换账号并注入代理断线恢复。该基线不等同于 500 个账号同时进行高吞吐传输。

记录测试机器、系统、构建配置、代理部署、负载、内存峰值、线程数、连接数、切换延迟及恢复时间。建议已加载账号切换到本地界面可操作的 P95 不超过 500 毫秒，不把远端历史下载计入该指标。

模拟连接测试用于发现资源和重连问题；真实 500 账号联网另行标记。未取得所需专用账号和代理环境时，报告容量验收未完成，不用模拟结果替代真实结论。

## 范围之外

- 账号凭据批量导入、批量修改个人资料，以及其他增强功能页面。
- 保证所有账号具有不同公网 IP，或保证多个不同代理服务绝不共享出口。
- 域名入口的安全引导解析、HTTP 和 WEB 代理在本隔离模式中的首版支持。
- 管控操作系统其他进程或用户另行启动的外部浏览器流量。
- 未经要求的依赖重建、Release 构建、远程 CI、应用发布及使用日常账号进行容量测试。

## 后续安排

按工程流程发布规格并拆分可独立验收的实施条目。优先打通账号绑定、保存恢复和连接阻断，再扩展数量、管理界面及容量验证。只有整体验收完成，才可宣称本需求完成。

## 设计参照

使用用户提供的 Pencil 设计节点：`fXxHp` 为账号头像快速切换，`yZOtg` 为账号管理，`Ecw6D` 为代理导入，`Yfmf8` 为代理列表。用户提供的设计样例不是运行数据；只实现本文明确包含的交互。

## 协议依据

- 官方[文件传输文档](https://core.telegram.org/api/files)定义通过 Telegram 获取网页文件的 `upload.getWebFile` 路径。
- 官方[群通话文档](https://core.telegram.org/api/group-calls)区分 WebRTC 模式与媒体分片下载模式；后者使用 `upload.getFile` 和 `inputGroupCallStream`。
- 官方[通话文档](https://core.telegram.org/api/calls)描述通过 API 协商通话，以及单独使用的 WebRTC STUN/TURN 连接参数。协议能力须与本客户端实际使用的传输路径共同验证。
